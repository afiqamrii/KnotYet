# Live QA and Number Guesser readjustment

## Changes

- Number Guesser uses a compact cream play panel, lavender range indicator, prominent input/submit controls, and a wider clue history. The panels size to their content instead of stretching into empty space. Phones stack history below the controls; short laptops use tighter spacing.
- Same-account auth refreshes update profile data without unmounting the protected game route and its multiplayer provider. Account changes still clear the previous account's session.
- Peer signaling and data-channel setup have a 15-second deadline. Restored rooms retry temporary host-ID conflicts and stalled joins. A signaling reconnect preserves a healthy data channel.
- Leaving or cancelling a room clears shared-round snapshots and returns to a fresh game introduction. Local Memory and Story progress stays separate.
- Automatic desktop chat docking collapses on a narrow viewport. Explicit open/minimize choices and drafts are preserved. The session clock hides below 360px so primary header controls fit.
- Room guidance no longer advertises an unenforced daily limit.

## Verification layers

1. Local deterministic checks use actual components/providers with controlled auth, database, or peer boundaries. `npm run test:games` includes auth-to-route lifecycle checks and the Number layout sweep at 320×740, 390×844, 1366×768, 1536×800, and 1280×600. `npm run smoke` covers public/account/chat/invite/room behavior.
2. `npm run test:transport` uses two isolated local browser clients with actual PeerJS signaling and WebRTC. It covers Number, Letter, This or That, Couple Match, Couple Guess, Wheel, Secret Number Race, reload/recovery, mobile layout, and leaving. It does not verify production authentication.
3. `npm run test:live:public` uses the deployed public UI without route interception or seeded state. The initial production run completed the 18-card deck, Memory Match, and Story Builder at 320, 390, 768, 1440, and 844×390 landscape, including refresh/back and export. No page, console, or network errors were recorded. Reports and screenshots are generated under `artifacts/live/`.
4. Manual production multiplayer testing uses two Chrome tabs signed into the existing account. The initial run reproduced the auth-refresh disconnect and temporary host-ID collision; those findings motivated the fixes above. The post-deployment results are recorded separately after release verification.

Screenshots for the redesigned Number states are generated under `artifacts/number-redesign/`. These are desktop Chrome viewport tests, not physical-device, Safari, separate-account RLS, or cellular-network certification.
